# AGENTS.md: Estia (package local-assistant)

Private assistant **Estia** (every install names its own: the config's `name`) on the local Gemma model (`local-worker`, an Ollama alias; see setup_assistant.md, "Model (once)"), reached over Signal. In code and docs "Gemma" means the model; the assistant's name (rules, greetings, notes, labels) is the config's `name` (default "Estia", `config.DEFAULT_NAME`): prompts take it at runtime (a `name` argument, a `{name}` template, `<name>` in the rules), never a constant. One Python process (the bridge) runs `signal-cli jsonRpc` as a child, answers the allowed user with Gemma and its tools (memory, links, host status, projects (an extra, off without `[projects]`), mail, calendar, web search, lights and plugs, Spotify, calls, reminders; photos and voice notes as input), sends a morning digest (calendar, then mail) and the reminders the user set (a text, and a Signal call for a wake-up call), now and then writes first (messages she starts herself, gated by code), keeps memory in one SQLite database, and runs always-on as LaunchDaemon `com.local-assistant.bridge`. Full explanation: `setup_assistant.md`. Design specs and plans are kept outside the public repo (`docs/superpowers/` is not tracked).

**Helping someone install Estia?** Follow `SETUP-WITH-YOUR-AI.md`: never handle secrets in chat, never run sudo yourself, `scripts/setup.sh` and `scripts/doctor.sh` do the work.

- Mail sign-in: `scripts/mail-login.sh <address> [--mail-only]` (asks for Calendars.Read too when the mailbox's calendar is configured; `--mail-only` without it)

## Conventions

- Python 3.13, **standard library only at runtime**; uv; ruff (line length 120); mypy --strict; type hints everywhere.
- TDD: a failing test first for every change and every bug fix. Prompt changes are checked with the Gemma test set (run it twice: Gemma is not deterministic).
- New features: agree the design first (an issue, or the PR description). Design specs and plans are kept outside the public repo (`docs/superpowers/` is not tracked). Conventional commits, no attribution trailers.
- Fixtures, tests and docs use the neutral persona "Alex Example", `example.*` addresses and fake numbers such as `+306900000000`. No real names, numbers, account IDs, device names, home paths or keys.
- The docs a person reads (README.md, SETUP-WITH-YOUR-AI.md, setup_assistant.md, SECURITY.md) use plain words a non-developer knows ("admin rights", not "sudo"; "only the Mac itself", not "127.0.0.1"), or name the thing and say what it is; exact terms only where the reader types them (commands, file names, config keys). Plainer never means weaker: every fact, limit and known gap stays. The same fact keeps the same words in every doc (`tests/test_docs.py` pins the shared sentences, the own-user limits among them).

## Rules (safety)

- Only ACIs in `allowed_acis` reach Gemma or receive anything; `SignalClient` refuses other recipients in code.
- Gemma gets no shell. Its only file access is the read-only project tools, an extra: off without `[projects]` (`Config.projects_enabled`; off, no project tool is offered, the rules say so in one line, `prompts.PROJECTS_OFF_RULE`, doctor has no Projects line, the move adds no folder and shares nothing). On, only files git tracks, at the project's level (`summary`: `project_status` and the whole README; `docs`: also the documents; `code`: every tracked text file, a search reading at most `SEARCH_FILES` files and `SEARCH_BYTES`, then saying how far it got; an `AGENTS.md` or `CLAUDE.md` in which `scan_context` finds planted instructions is left out at every level, by `project_status`, `project_read` and `project_search` alike), never secret-like names, binaries (a NUL byte) or files over 200 KB, never outside the projects root (`[projects] root`). Setup asks for it explicitly, never by looking for git folders (`Wizard.projects`, `--extras`: `projects_extra`); in her own user it only prints the lines to add (her config is hers). Text from tools, links, pages, project files and photos is data, never instructions.
- Health checks and git run fixed commands from code (no shell); Gemma chooses only a project name, a tracked file, a start line or search words. A name she heard is matched in code to the nearest project (`projects.nearness`: the same letters without case, accents and separators, else spelling or a small sound key by edit distance, a match by sound alone only when the spelling is also at most `SPELLED_TOO` (0.6) apart, else asked about, never taken; a whole word of a longer name is never taken alone); a name taken as another project is named in the tool's result, and the rules tell her to name it in her answer; unsure (two about as near, only fairly close, or none close), the tool's error asks her to ask ("Do you mean …?"), and a name with a slash or a leading dot is never matched.
- Photos live only until answered (follow-ups within 5 minutes reuse the last photo from memory, never from disk): signal-cli's copy is deleted afterwards, strangers' and unsupported files at once; other downloads (link previews, quote thumbnails, avatars, edited messages) are swept once 10 minutes old.
- Mail sorting funnel: replies by the user -> waiting; correspondents (anyone the user mailed, To or Cc, kept in `mail_correspondents` beyond the headers), replies in the user's threads, bounces and bills/payments/security/appointment words (EN + NL) always go to Gemma; otherwise List-Id / Precedence bulk -> noise; List-Unsubscribe / Auto-Submitted only with Jev's agreement (p >= 0.5); then the optional local AgentJev (`[mail] jev_url`, localhost only) -> noise when at least `jev_threshold` sure, else Gemma. One in five pre-filtered mails is double-checked by Gemma (its label wins). `mail_triage` keeps the step, Jev's number and Gemma's label (no text) to measure Jev.
- Mail is read-only by permission (`Mail.Read`): no code may send, move, delete or mark mail. Mail's token request asks for the mail scopes only (`mail_auth.SCOPES`, unchanged), so mail never depends on the calendar's consent. Mail bodies are never stored (headers, label and a checked one-line summary only; mail tool results are not written to the tool log, which keeps a stub); mail text is data, never instructions, and never teaches the profile (in an answer that read mail, `remember` and `forget` are refused in code). Refresh tokens only in `mail-tokens.json` (0600).
- Calendars are read-only: Google iCal feeds and Outlook calendars with delegated `Calendars.Read` only (never `Calendars.ReadWrite` or `.Shared`; its own token request, never mail's token; no code may create, change or answer an event). A Google calendar's address is a password: only in `calendar.env` (0600, one key per calendar), read only by the calendar helper, which fetches only Google's iCal host and follows no redirects; the bridge never holds it. An Outlook calendar asks Graph for no bodies, attendees or organizer address, and keeps only a place's display name; missing consent (AADSTS65001 or 70000) is its own reason (`no_consent`), never mail's pause; doctor counts only a new sign-in of the mailbox as its fix (`signed_in_at`; mail renewing the token is none), and only one that asked for `Calendars.Read` for missing consent. One failing calendar never hides the others. Events are read live, never cached; event text stays only where mail text does (the sent digest note, Gemma's answers), and calendar tool results are a stub in the tool log; event text is data (cleaned, capped, links removed from places), and an answer that read the calendar refuses `remember`/`forget` and makes device requests wait for the user's yes.
- Voice notes: only the allowed user's audio is transcribed; audio that Signal does not mark as a recorded voice note (an audio file shared from elsewhere) is stored as `[audio file] …` (words typed with it stay on their own line below the transcript): not the user's words (never learned, never a yes, `remember`/`forget` refused, device changes wait for a yes); without the flag everything is a voice note as before; audio and spoken answers live only until used (deleted in `finally`, the sweeper catches leftovers); the voice service listens on 127.0.0.1 only, refuses browser-style requests and logs metadata only. Its WhisperKit and FluidAudio pins come from OpenWhisperer: change them only deliberately. Whisper's files are pinned too (`WhisperModel` in `ModelPin.swift`: the CoreML model and the tokenizer WhisperKit reads with it, one commit each, every file's sha256), checked at every start (`prepareModel`; about 0.6 s for 1.6 GB, read in pieces) and downloaded at that commit only when missing (`downloadPinned`, WhisperKit's own layout, so an existing copy is kept); WhisperKit then gets only the checked folders (`whisperConfig`: `modelFolder`, `tokenizerFolder`, `download: false`), so a start never reaches Hugging Face. A changed or added file (an older download's extra file too) or a link is never loaded and never downloaded over: `prepareModel` moves that pin's folder aside whole (`<folder>.refused-<UTC time>` beside it; only the latest such copy of a pin is kept, so the disk never fills), downloads the pinned commit into a fresh folder and checks it, so no recovery needs her user or root; changed again, or a folder that cannot be moved, listening stays `failed` with the service up (no restart loop); a failed download, or files still missing after it, exits so launchd tries again.
- Calls: only allowed ACIs are answered; strangers are ignored (never rejected: that would send them something); `accept_call`/`hangup_call`/`start_call` refuse other ACIs in code. Call audio lives only in memory; turns are stored as `[call] …` text (answered/sent at once, so recovery never re-sends them); logs hold metadata only. A device yes on a call counts only after she finished asking (the question's last sentence cannot be talked over); the question itself is spoken in code's words (`Devices.question`), so a yes never confirms something the caller did not hear. At the start of an ordinary call (not a practice call: `call_started(practice=…)`), with `[calendar]` or `[mail]`, code reads the call's glance (`App.CallGlance`: `MailDigest.glance` at once, a quick local read, and `CalendarTools.glance` in a task; `prompts.call_glance`): today's counts and times only, never a title, place, calendar name, sender or subject (that text would make the call outside text), last in the system prompt; she may offer the rundown (once: her first answer given with the glance that asks something, `CallGlance.note`); a whole yes right after it (`language.is_yes`: the call's language or English) makes code read today's calendar and the mail digest itself (`app.rundown_reads`, at most once a call: `calendar_agenda` for today and `mail_digest`, each when set up, run through `Brain.answer(reads=…)` as her own tool calls, logged and counted like hers; live evals: on her own she called no tool after the yes), else she reads details with the tools only when asked (that answer is outside text as ever); the mail counts are there from the first turn, which waits for the calendar's at most `GLANCE_WAIT_SECONDS`, later turns take them once read; each part has its own try (a calendar that fails in any way is "not read just now", the mail counts stay); it is dropped at the call's end. What stops her is `[calls] barge`: "loudness" (default, today's rule) or `barge = "speech"` (the voice service's speech detector, `POST /vad?stream=<call>` with 256 ms chunks: p >= 0.99 and the chunk louder than max(3x floor, 150)); the other rule is a shadow, never acted on (`call_audio.Barge`): counted at most once a clip, only when the rule in charge did not stop her in that clip or its stop was no words or her own voice (`Barge.false_stop`), with stops and "would have" kept per rule; one end-of-call log line (metadata) names the configured rule, why loudness took over if it did, the counts per rule, the detector's chunks, slowest answer and failures by kind (`timeout`, `http`, `late`); the loudest chunk the level gate turned away at p >= 0.99 is one log line a clip (numbers only). No detector (`voice.detector_state`: loading, unavailable, old voice service, not ready), or 3 failed or late (> 600 ms of audio) answers in a row in a call, means loudness for the rest of it, and a call never waits for the detector; the pre-roll reaches back to the first frame of the latest chunk an answer may stop her on (`PREROLL_FRAMES`). After every stop the transcript is compared with what she already played (the sentence before and this one up to the stop, `calls.played_part`): her own voice (`calls.is_own_voice`: >= 3 of her content words, function words left out, >= 60% of the transcript's, and >= 3 words in a row as she said them; a stop, yes or no word she did not say makes it the caller's; Japanese by characters) carries on like a cough, never reaches Gemma, and the first time in a call a stop then needs 1.5x the level that stopped her (once, never compounding).
- Her voice loading (`voice_ready.ReadyNote`, with `[calls]` only): a call needs both engines ready (`stt` and `tts`); until then a ring from an allowed ACI rings out (never rejected) with `prompts.CALL_NOT_READY` (at most once in `NOT_READY_NOTE_SECONDS`, 10 minutes) and every such ring is reported to `ReadyNote.missed(aci, promised)` (`promised`: this ring got the note). When the voice turns ready, code sends `prompts.VOICE_READY` as a note (never in Gemma's history): at once to a caller who rang meanwhile, also in quiet hours; to every allowed ACI when a read `LONG_LOAD_SECONDS` (120 s) or more after the bridge started still said not ready (a voice never seen not ready, or ready sooner, is no long load: a slow start-up alone texts nobody), held until the end of the initiative's quiet hours, 22:00-08:00 when it has none (`voice_ready.QUIET_HOURS`; never waking anyone). At most once per bridge start for each ACI, except that a later not-ready note (its "I'll text you") re-arms one for that caller (ruling: the promise wins; bounded by the not-ready note's 10 minutes); nothing while locked (checked before each send; it waits for `/unlock`); a call that connected (`CallManager(reached=…)`, after accept and connect or a placed call picked up, never one that only rang) owes no note and is left out of the long-load note; the health is read every 15 s from the bridge's start until it is ready, and after a missed call until it is ready, never otherwise, and again right before a held note goes out. Logs name the reason, never an ACI. The end of a move, a setup and a voice deploy says `ownuser.voice_end`: "voice: ready" (both engines); still loading, with `[calls]` (`ownuser.calls_in`: the move from her config text, the deploy as her with `--read-calls`, setup from the config it loaded, never in her own user) it reads again for up to `VOICE_WAIT_SECONDS` (150 s: the bridge's 120 s plus two of its polls) and then says `ownuser.VOICE_LOADING` (so the text surely follows), without `[calls]` `VOICE_LOADING_NO_CALLS` at once; a Ctrl-C there ends only the wait (the move's comes after the move is done, outside the restore). The voice service is asked only on the live Mac (`voice_health(live)`), never under a test root or a rehearsal.

- The model always runs on the Mac: a model name whose tag ends in `-cloud` or `:cloud` (an Ollama cloud model: it runs on Ollama's servers) is a config error (`config.is_cloud_model`), and the bridge always reads the alias's entry in `/api/tags` (`OllamaGemma.model_entry`, `app.model_pin`, with or without `model_digest`) at the start, every 5 minutes and before every chat (`ModelPin.ensure`: one local request, no grace period): an entry with `remote_host` or `remote_model` (Ollama 0.40.0's marks of a cloud model; `gemma.is_remote`) pauses every Gemma call like the digest below (`ModelPin.why == "cloud"`; code's notes `prompts.MODEL_CLOUD` and `MODEL_CLOUD_RESUMED`, spoken `MODEL_CLOUD_SPOKEN`; `security.model_cloud` in `status.json`), and doctor's Model line is ✗ with the fix. The terminal draft (`initiative --draft`) checks the same before it asks the model. The model's pin: with `model_digest` (64 hex digits, "sha256:" optional) the alias's digest from `/api/tags` is compared at the same reads; any other digest (or the alias gone) pauses every Gemma call (a model swapped in between a read and its chat still gets that chat; the owner's account, which runs Ollama, is outside the pin) (`PinnedGemma` raises `ModelPausedError`): a message gets code's note (`prompts.MODEL_PAUSED`), never a Gemma answer, the pause and its end are one note each, and `status.json` keeps `security.model_paused`. An entry that cannot be read changes nothing (the next chat reads it again). The evals hold to the same: `EVAL_MODEL` and `EVAL_BASE_URL` are refused for a cloud name or a host off the Mac, and `run_cases` stops before any case when Ollama lists a cloud model. Without `model_digest` only a cloud model pauses, and doctor shows ! with the line to pin. AgentJev's Host and Origin check lives in its own repo (SECURITY.md, known gaps).
- History retention: `[privacy] keep_days` (left out: kept, as before) deletes messages, pages and tool calls older than that with their FTS rows (`Store.prune`, then each index's `optimize`), once a night between 03:00 and 05:00 when nothing else runs (state `privacy:pruned_at`), then `Store.compact` (checkpoint, VACUUM, checkpoint; it blocks the database for a moment). Open reminders, open check-ins and the initiative log are never touched (their messages stay); the profile stays, its links to deleted messages and pages are cleared; an ended conversation without messages goes with its summary. `PRAGMA secure_delete = ON` in `Store.open` overwrites deleted rows in the file.
- Logs are bounded in-process, never by newsyslog or root: `bridge.log` is a `RotatingFileHandler` (10 MB x 5 older files), `launchd.log` (the bridge's stdout and stderr) is emptied when over 10 MB at the start and before any write (`app.cap_streams`), and so is `voice.log` (`LogCap` in VoiceCore); every file is private (umask 077).
- Injection residue across turns: while her context still holds a reply or summary that followed outside text (`ContextBuilder.after_outside`: an earlier message of the conversation, in the window or summarised, whose answer used a mail, calendar, project, page, history, web or map tool, or an audio file or a photo; `/new` starts without it), `set_reminder` stores only text that overlaps the user's own message (`reminders.own_words`: every number and link in it from the message, and at least half its words; scripts without spaces by character), else code's line says why and points to `/remind` (`REMINDER_REASONS["not_your_words"]`; Gemma's tool result stays `REMINDER_OWN_WORDS`). Links in her answer after outside text (this answer's or the context's) are defanged in code (`brain.defang_links`: `example[.]com/login`) unless the user's message has them; an answer that searched the web still loses its links; the Sources note stays code-written. A practice answer (`brain._practise`) runs no tool, so no `set_reminder` and nothing for the overlap rule; its links follow the same rule over the practice conversation (an audio file or a photo in it, or answered now); the chat's outside text is not in its context, and practice turns never count as outside text for the chat.
- The JVM signal-cli installer (`tools/call-tunnel/install-signal-cli-jvm.sh`) pins AsamK's release key: the imported key's fingerprint (`gpg --with-colons`) and the signature's `VALIDSIG` fingerprint (its primary key) must both be FA10826A74907F9EC6BBB7FC2BA2CD21B5B09570, or it exits 1 before anything is unpacked.
- No secrets or personal identifiers in the repo: they live in `~/.config/local-assistant/config.toml` (0600; in her own user `/var/estia/.config/local-assistant/config.toml`). Logs hold metadata only, never message text. `scripts/privacy_scan.py` enforces this (verify.sh and the opt-in hook): private file names, keys, addresses, numbers, UUIDs, home paths and the owner's own config values (whole words; setup keys such as paths, local addresses and labels are left out: `SETUP_KEYS`); its output names the rule or config key, never the value.
- `status.json` (part_status) holds part names, times, fixed reasons and HTTP status numbers only: never message, mail, event, search or device text, addresses or keys. Recording never raises into the part it watches.
- The welcome (`prompts.welcome`) is written by code and starts only when the store has no messages at all (a fresh install; an update never sends it). It is owed once to each ACI allowed at that start (`welcome_owed`, then `welcome_sent` in `state`); an ACI allowed later never gets it. It is stored only after it was delivered, as a sent note, so it never enters Gemma's history and recovery never sends it again; an ACI it could not reach gets it at the next start.

## Gotchas (learned the hard way)

- A note sent before `recover()` (at the start) goes out twice: recovery resends every pending outgoing message of the last 10 minutes. Start-time notes (the model's pause) are sent after recovery.
- `status.json` is written whole: `PartStatus` keeps the `security` section beside the parts, so one writer never drops the other's facts.
- signal-cli always names the sending device (`sourceDevice`); a test envelope without it is held (the fake signal-cli adds device 1, as signal-cli does, when a test leaves it out). A `Decision` rebuilt in the app must keep its `device`.
- The venv is not relocatable and uv's Python lives in the owner's home (0700 for `_estia`): a release holds its own interpreter and builds its editable `.venv` at its final path (code finds its files through `Path(__file__).parents[2]`).
- launchd opens `StandardOutPath` and `StandardErrorPath` for appending: emptying the file (ftruncate) is enough, writing goes on at its new end. It opens them as root in a folder she owns: whether it follows a link there is untested (docs/e2e-checklist.md, 111).
- A deploy's health check counts only a new bridge process with `last_alive` after the restart (`Deploy.health(restarted, old_pid)`): the old bridge keeps writing it during the minutes the build takes.
- The freeze keeps each file's times (`os.utime`): the bytecode `uv sync` and `compileall` wrote checks them, and her user cannot write `__pycache__` in the release.
- A link check by its text is not enough: `sub/b -> ..`, `b -> .` and `b/b/../../..` leave the tree after the kernel follows the links; `deploy._check_links` and doctor's code check use `realpath`. Root opens build files with `O_NONBLOCK` (a FIFO swapped in must not hang it).
- The owner's `sudo` from a Claude Code `!` command has no terminal for the password: every sudo command goes in the person's own Terminal window.
- macOS `chmod -R +a` sets the ACL entry on the target of every symbolic link in the tree (macOS 27; the man page's "no link followed" holds for modes only), and `chmod +a` on a link without `-h` does too; `chmod -h +a` changes the link itself. `chmod -R` and `-h` cannot be combined. An ACL entry for a user that does not exist cannot be set ("Unable to translate"): tests use the current user.
- Git trusts a repository another user owns only through `safe.directory` (`GIT_TEST_ASSUME_DIFFERENT_OWNER=1` makes every repository look foreign in tests); `-c` on the command line is honoured, and it reaches the child gits `git status` runs in submodules.

- Gemma imitates whatever is in its history: code-written notices must stay out of it, and earlier tool calls must be replayed (short), or it starts claiming saves it never made.
- Chains of tool calls (one `remember` per fact) are unreliable in real chats; do structured extraction in code (JSON schema) instead.
- One signal-cli process per account: stop the bridge before running signal-cli by hand.
- `sqlite3 -readonly` cannot open the WAL database while the bridge is stopped (no `-shm` file).
- `sips -Z N` also enlarges smaller images: read the size first (`photos.prepare` does).
- A photo arrives as one JSON line of base64 from signal-cli (20 MB → 27 MB): the reader limit is 32 MiB.
- Editing a file twice within a second with the same size can leave stale `.pyc` files: clear `__pycache__` if a test disagrees with the source.
- The Neural Engine compiles a model on its first use: about 15 minutes for Whisper large-v3 turbo, cached per process name and macOS build (`~/Library/Caches/voice-service/`), so again after a macOS update. The voice service warms up at start and says "loading" until then. It compiles again per user: about 15 minutes after the move into her own user (live, 13 Oct), although the move copies the cache. Calls go unanswered meanwhile (hence the ready note).
- WhisperKit given `model:` and `downloadBase:` lists the repository at `main` and asks Hugging Face about every file at every start, fetching whatever changed; with no tokenizer in its folder it fetches one from `openai/whisper-large-v3` at `main`. Hence `whisperConfig` and the pinned tokenizer. WhisperKit names Hugging Face's address itself for that download step (`Constants.defaultRemoteEndpoint`), so `HF_ENDPOINT` cannot show that a start stays offline; `sandbox-exec` with outgoing connections denied can (SwiftPM's own sandbox cannot nest: `swift test --disable-sandbox --skip-build`). A Hub download keeps its records in `.cache` at the top of the repository's folder (inside the tokenizer's, beside the model's folder): `HubPin.check` leaves it out there only.
- `swift test` with only the Command Line Tools can lose the Testing macros plugin after a failed build; `tools/voice/Package.swift` names its folder (`-plugin-path`).
- A calendar feed is outside input: `recurring-ical-events` loops forever on `INTERVAL=0`, floods on rules finer than daily, crawls on rules that never occur and on long events overlapping its search windows; one unreadable rule used to stop the whole feed. The helper drops unreadable, never-advancing and finer-than-daily rules, expands each repeating event on its own (0.5 s, 400 occurrences) with `between()`, and has a hard limit (15 s; the bridge 30 s).
- Setup prints each command before it runs it: a secret typed at a hidden prompt (captcha link, SMS code, PIN) is shown only as a placeholder, or it lands in the terminal (and an AI's transcript), and it never goes into a program's arguments (`ps` shows them to every user of the Mac): register, verify and setPin go to signal-cli as one JSON-RPC request on stdin (`harden.json_rpc`; signal-cli 0.14.9 offers register and verify only in multi-account mode, `jsonRpc` without `-a`: `setup.registration_argv`).
- Only Kasa devices are tested: older ones speak the local protocol without a login, newer Kasa firmware (KLAP) needs the TP-Link login. Tapo devices go through the same library with that login but are untested; Tapo firmware with the TPAP login is not supported by python-kasa 0.11.0.1 (the helper says "unsupported"). The `tapo` names in paths and config keys cover Kasa too.
- Homebrew's signal-cli (GraalVM native) cannot place calls: it lacks reflection metadata for `TurnServerInfo` (also on master). Calls use the JVM build of the same version (`tools/call-tunnel/install-signal-cli-jvm.sh`); its launcher must not get `-D…` arguments (IPv4 goes in `JAVA_OPTS`).
- macOS stretches 10 ms sleeps to ~90 ms in background or idle processes (Claude Code jobs included): an audio clock must run on a real-time (time-constraint) thread, as our call helper's patch does, or the call sounds garbled. Test call timing in frames, never wall time.
- Call audio: estimate the line's floor from the quietest frames (capped), never from the first frames alone, or a caller who talks at once is not heard; drop what came in while she was thinking only when a new answer starts, never between two sentences.
- Barge-in by speech decides once per 256 ms chunk (FluidAudio 0.15.8's `VadManager` takes exactly 4096 samples at 16 kHz; shorter chunks are padded and break detection), so it stops her about 0.1 s later than loudness. Silero ignores loudness above a whisper: the level gate keeps a far voice out, whispers are mostly missed, and a radio, singing or a passenger counts as speech. Chunks go out in order (the service keeps one detector state per call); the answer lands on a later frame, so tests count it in frames.
- `recover` resends outgoing messages that are `pending` or `failed` (within 10 minutes): a note that must never go out again (a reminder note that may have gone out, one given up on) is set to `ignored`, not `failed`.
- Outgoing calls (signal-cli 0.14.9 `startCall`, experimental upstream): the `RINGING_OUTGOING` event comes before `startCall`'s reply, so the call id is not known yet when it arrives (`CallManager._dial` buffers events); `CONNECTING` only means it reached the phone. The end reasons (`ring_timeout`, `remote_hangup`, `remote_busy`, …) and pipe-mode audio on an outgoing call still need the live test (docs/e2e-checklist.md, 83-86).
- `sysadminctl -addUser … -roleAccount` ignores `-home` and `-UID` (macOS 27): her account record keeps `/var/empty`, and setting `NFSHomeDirectory` on her record with `dscl . -create` fails with eDSPermissionError even as root. Her home is set explicitly instead: `HOME` and `CFFIXED_USER_HOME` (Foundation, the Swift voice service) in the service files, `-Duser.home` in `JAVA_OPTS`, signal-cli's `--config`.
- A folder root makes inside her home stops a `chmod -R` run as her (live: the parents of an earlier copy kept aside). The chmod after the copy names exactly what was copied and the folders on the way, never her whole home.
- Python's `mkdir(parents=True, mode=…)` gives only the last folder that mode; the parents it makes get the default mode (umask). Make each level with its own mode, or `chmod` it after.
- A dry run of the move runs as the owner: after a first try her home is 0700 and hers, so it cannot look inside (it says what it would do). A shell glob cannot expand inside her 0700 home either: name paths exactly (hence `remove-old` lists her copies itself).
- A test of the owner's shell scripts sets `ESTIA_TEST_ROOT` to a fake tree: they ignore `ESTIA_ROOT` on purpose, and once she is moved the live `/Library/LaunchDaemons` shows her moved: a test without it reads the live system and, where she is moved, runs the real `/usr/bin/sudo` (so `run_script` in `tests/test_scripts.py` always sets one: `/var/empty/estia-test-root`, which can never exist, unless the test names its own). Python tests get their own empty `ESTIA_ROOT` from `tests/conftest.py` (`no_live_system`, which also refuses the live voice service); doctor's "Always on" stat'ed the live service file 117 times before it followed `estia_root()`.
- `lsof` shows a user only their own processes, so doctor (as her) lists listeners from `netstat -anv -p tcp` (every user's sockets with pid) and the program from `proc_pidpath` (ctypes, which names other users' processes too), merged with the listeners of the user doctor runs as, from `lsof` (the owner's only in `scripts/doctor.sh` before the move, and in harden). In one sandbox, `netstat` started from uv's or Homebrew's Python listed no internet sockets while zsh's did; as her, a netstat that lists nothing leaves the owner's programs unnamed: untested on the live Mac (docs/e2e-checklist.md, 122).
- A wait after the move is done (the voice line) must never reach the restore: a Ctrl-C there ends only the wait. Inside the move's `try`, any interruption brings her old setup back.
- The website (estia.fun, its own repo) checks the README with drift tests (`tests/drift.test.mjs`, `ESTIA_REPO=<checkout>`) that read some README sentences word for word (`tests/test_docs.py` pins many of them here, each marked for the site): a changed one turns the site's tests red until the site matches, so name every changed one (old and new) for the site.
- A setting that names a file the user may move, replace or delete (the `avatar` picture) is checked where it is used, never at load: a `ConfigError` stops the always-on bridge (launchd restarts it every 30 s, offline, with no way to say why over Signal). Only the setting's form is a config error; a file that cannot be used is a logged skip and a doctor warning.
