# AGENTS.md: Estia (package local-assistant)

Private assistant **Estia** (every install names its own: the config's `name`) on the local Gemma model (`local-worker`, an Ollama alias; see setup_assistant.md, "Model (once)"), reached over Signal. In code and docs "Gemma" means the model; the assistant's name (rules, greetings, notes, labels) is the config's `name` (default "Estia", `config.DEFAULT_NAME`): prompts take it at runtime (a `name` argument, a `{name}` template, `<name>` in the rules), never a constant. One Python process (the bridge) runs `signal-cli jsonRpc` as a child, answers the allowed user with Gemma and its tools (memory, links (a YouTube link: its captions), host status, projects (an extra, off without `[projects]`), documents (an extra, off without `[documents]`: the PDFs in the owner's `~/Estia-KB` and the ones the user sends), mail, calendar, web search, lights and plugs, Spotify, calls, reminders; photos and voice notes as input), sends a morning digest (calendar, then mail) and the reminders the user set (a text, and a Signal call for a wake-up call), now and then writes first (messages she starts herself, gated by code; the evening note, code's three questions at the user's time, off by default), keeps memory in one SQLite database, and runs always-on as LaunchDaemon `com.local-assistant.bridge`. Full explanation: `setup_assistant.md`. Design specs and plans are kept outside the public repo (`docs/superpowers/` is not tracked).

**Helping someone install Estia?** Follow `SETUP-WITH-YOUR-AI.md`, a hand-over: check the Mac first, run only the checks, `scripts/setup.sh --dry-run`, `scripts/doctor.sh` and the other read-only commands its list names (SETUP-WITH-YOUR-AI.md, "You may run only these"), brief every question in one message, then the person runs `scripts/setup.sh` in their own Terminal window (it reads every code from that terminal, never from stdin) and pastes back the doctor's output. Never handle secrets in chat, never run sudo yourself.

## Conventions

- Python 3.13, **standard library only at runtime**; uv; ruff (line length 120); mypy --strict; type hints everywhere.
- TDD: a failing test first for every change and every bug fix. Prompt changes are checked with the Gemma test set (run it twice: Gemma is not deterministic).
- New features: agree the design first (an issue, or the PR description). Design specs and plans are kept outside the public repo (`docs/superpowers/` is not tracked). Conventional commits, no attribution trailers.
- Fixtures, tests and docs use the neutral persona "Alex Example", `example.*` addresses and fake numbers such as `+306900000000`. No real names, numbers, account IDs, device names, home paths or keys.
- Signal shows Markdown as typed ("**bold**" with its asterisks). Every text goes out through `App._deliver`, which turns markup into Signal's text styles (`signal_text.styled`: **bold**, ~~strike~~, `code` and closed fences as monospace, a "# heading" line bold, "- " and "* " line starts "• ", *italic* only with clear edges; never underscores, a web address (punctuation after it is the sentence's), math such as 2*3 or 2**3, a closing marker after a slash or a backslash (a glob: "**/node_modules/**"), a lone or unbalanced marker, or markers across lines; a line where a dropped marker would sit inside a web or mail address of the result ("**evil**.com") goes out as typed) and `SignalClient.send` sends them as signal-cli's `textStyle` ("start:length:STYLE", UTF-16 code units; one bad entry fails the whole send in signal-cli, so a list that `signal_text.valid` refuses is dropped and the text goes out without). The stored text keeps its markup (history, search, a resend after a restart converts again); a conversion that fails sends the text as written; a footer goes out in italics. ## Gotchas (learned the hard way)

- A note sent before `recover()` (at the start) goes out twice: recovery resends every pending outgoing message of the last 10 minutes. Start-time notes (the model's pause) are sent after recovery.
- `status.json` is written whole: `PartStatus` keeps the `security` section beside the parts, so one writer never drops the other's facts.
- signal-cli always names the sending device (`sourceDevice`); a test envelope without it is held (the fake signal-cli adds device 1, as signal-cli does, when a test leaves it out). A `Decision` rebuilt in the app must keep its `device`.
- The venv is not relocatable and uv's Python lives in the owner's home (0700 for `_estia`): a release holds its own interpreter and builds its editable `.venv` at its final path (code finds its files through `Path(__file__).parents[2]`).
- launchd opens `StandardOutPath` and `StandardErrorPath` for appending: emptying the file (ftruncate) is enough, writing goes on at its new end. It opens them as root, so they live in `/var/log/estia`, a folder only root can change: no link of hers is ever followed there (an install from before keeps them in her folder, where a program of her account could make root write into a file it names, until `--update-tools` and one more deploy: doctor's ✗ Services, a known gap in SECURITY.md until then; the docs' update order is deploy, `--update-tools`, deploy again).
- A deploy's health check counts only a new bridge process with `last_alive` after the restart (`Deploy.health(restarted, old_pid)`): the old bridge keeps writing it during the minutes the build takes.
- The freeze keeps each file's times (`os.utime`): the bytecode `uv sync` and `compileall` wrote checks them, and her user cannot write `__pycache__` in the release.
- A team ID is a claim, not a proof: a copy of `/usr/bin/true` signed ad hoc with `codesign -s - --team-identifier 3MU9H2V9Y9` passes `codesign --verify --strict` and `codesign -dv` prints `TeamIdentifier=3MU9H2V9Y9` (`Signature=adhoc`; live 15 Oct). Only a requirement proves Apple's chain: `codesign --verify --strict -R '=anchor apple generic and certificate 1[field.1.2.840.113635.100.6.2.6] exists and certificate leaf[field.1.2.840.113635.100.6.1.13] exists and certificate leaf[subject.OU] = "3MU9H2V9Y9"'` (exit 3 for the forged copy; every program, library and metallib of Ollama's v0.40.4 passes, metallibs included, 15 Oct).
- A link check by its text is not enough: `sub/b -> ..`, `b -> .` and `b/b/../../..` leave the tree after the kernel follows the links; `deploy._check_links` and doctor's code check use `realpath`. Root opens build files with `O_NONBLOCK` (a FIFO swapped in must not hang it).
- The owner's `sudo` from a Claude Code `!` command has no terminal for the password: every sudo command goes in the person's own Terminal window.
- macOS `chmod -R +a` sets the ACL entry on the target of every symbolic link in the tree (macOS 27; the man page's "no link followed" holds for modes only), and `chmod +a` on a link without `-h` does too; `chmod -h +a` changes the link itself. `chmod -R` and `-h` cannot be combined. An ACL entry for a user that does not exist cannot be set ("Unable to translate"): tests use the current user.
- Git trusts a repository another user owns only through `safe.directory` (`GIT_TEST_ASSUME_DIFFERENT_OWNER=1` makes every repository look foreign in tests); `-c` on the command line is honoured, and it reaches the child gits `git status` runs in submodules.

- Gemma imitates whatever is in its history: code-written notices must stay out of it, and earlier tool calls must be replayed (short), or it starts claiming saves it never made.
- A tool's description is in every request, calls included: "(a YouTube link: its captions)" and "or a YouTube link read in the last 10 minutes" in read_link's took call_goodbye from 88% to 58% (Fisher p = 0.001; the request otherwise byte-identical). Say a feature in code's per-turn lines (`prompts.VIDEO_KEPT`), never in a shared description. Without it, "send me the full transcript of <link>" got "I can't access YouTube" (video_full_transcript 0/10), not the link; code's line `prompts.VIDEO_IN_MESSAGE`, only when the current message holds a YouTube link, brought it to 5/5 once it ended with "give this link instead: <link>" (the link in brackets earlier in the line: 2/5, she said where to find the transcript without the link). With that line alone she called the link "the full transcript" 3 of 5 times; the line now says the link opens the video and never to call it the transcript, still ending with the link: 10 of 10 named it the video (14 Oct; the case's judge, `calls_link_the_transcript`, fails the other wording).
- The list of what she can do (`prompts.capabilities`) in a call's rules took call_goodbye from 24 of 30 to 9 of 30 (14 Oct; she said goodbye without end_call): a call's rules leave it out (`prompts.without_capabilities`, `ContextBuilder.build(call=…)`), so a call's request is byte for byte the one from before the list.
- Repeats of one case in one eval process are not independent samples: the same request ran 0 of 10 and then, a few minutes later, 10 of 10 (`video_summary` with hearth, 15 Oct; Ollama's prompt cache on MLX is the likely cause). Compare two prompts with their cases run in turn in one process (A, B, A, B, ...), never as two batches. Even in turn a prompt can stay in one mode for many runs (video_auto 8 of 8, then 1 of 8 an hour later, the same request): for independent samples put a random tag first in every system prompt of the measurement, for both prompts alike (`Request 3f9a….`; 15 Oct, the evening note's line).
- A judge must see what the user gets. Markers cannot see a spoken quip ("Mondays are the perfect excuse to pretend your coffee is a magic potion"), and a 😄 after a plain fact is no joke: 15 Oct, `jokes_when_invited` passed hearth on the emoji its style asked for, `call_no_joke` passed the chat style's quips on calls 14 of 15, and `call_goodbye` (end_call and no list) passed "機", "call", "thought: ]" and "// Final message ends the call.". The evals' Gemma judge (`judged`: temperature 0, one fixed yes/no question, the reply as data in `<reply>` tags) is checked on logged replies before use (the chat style's quips 9 of 15 yes, the call style's answers 0 of 15) and keeps the marker checks beside it; `spoken_ok` fails junk (a tag or its piece, "//", a lone "thought", another script on an English call, under 3 words), `call_goodbye` needs a goodbye word, and a case that copies her style's words (`copies_style`, 6 in a row) fails: a line that names its eval's question is recalled, not followed.
- Gemma 4 sometimes leaks its thinking channel into an answer ("thought\n<channel|>Goodbye!", end_call turns, evals 15 Oct): a caller would hear "thought". `brain.without_thinking` drops everything up to the last `<channel|>` before anything else reads the text, practice turns included.
- An older release on a newer database: the schema only moves forward, and older code reads the rows it does not know. A release from before the evening note (v11) put back by a deploy's rollback or deployed from an older commit raises KeyError 'evening' in `/status` and doctor (`prompts.INITIATIVE_KINDS[kind]`) for 4 weeks after an evening note was skipped or failed while the initiative is on, and counts sent evening notes toward `max_per_day` (setup_assistant.md, Updates: a known gap). Keep a new kind's rows where older code never reads them, or say the limit. A release from before the two parts (v13) reads both as one 6,000-character profile: its consolidation and learning may delete facts to fit (setup_assistant.md, `profile_facts`: no "remember" until the next deploy).
- An empty answer (neither words nor a tool call that may run; `brain._usable`) is asked again once with `EMPTY_NUDGE`, and the retry's result is read: one warning when it is empty too (then `CONFUSED`), one info line when it answered. Each try is one line of metadata, never words (`brain._Shape`: path call/text/document/practice, attempt, finish_reason, completion_tokens and prompt_tokens (`Completion`; `reasoning_chars` keeps only the size of Ollama's reasoning field), max_tokens, tools offered and tool calls returned, content characters raw and stripped, ms, after a tool result, language code; the practice path's broken reply too). An answer the filters at the end of the tool loop leave empty (`brain._filtered`: without_thinking, without_fake_notices, without_written_end_call) is one warning naming the filter and the lengths. No logprobs: `logprobs: true` would show the dropped thought but turns off speculative drafting (research of 17 Oct, fix 7, not built). On a call `on_retry` (`Host.call_turn` → `App.call_turn` → `Brain.answer`, once an answer, also a practice turn's broken first try) makes `CallManager._turn` say an acknowledgement at once while the retry runs: `_pick_acknowledgement`, `acknowledge` on, no device question waiting, none at the turn's start and none on the turn before, and none after a thinking or checking line (fillers on: it would come in the wrong order, review M1); the few-words rule does not apply (with it, only turns that had one at their start would qualify); it counts as the turn's, so the next request gets none.
- Ollama picks Gemma 4's prompt by the model's name (e2b, e4b: small; 12b, 26b, 31b: large; Ollama 0.40.4, `server/renderer_resolution.go`), and the alias `local-worker` names no size: it got the prompt for the small models, without the empty thought block Google's prompt for 12B and larger ends with when thinking is off, and about 1 answer in 10 came back empty (11 to 17 Oct; the likely cause, by elimination). - English speech (VoiceCore `SpokenEnglish`, Kokoro only) is one list of passes in one order (`SpokenEnglish.order`, pinned by a test): a pass that runs early owns its text (times take their colon, dates their numbers, units their amounts; symbols run just before the numbers are read, since their rules look at the digits).
