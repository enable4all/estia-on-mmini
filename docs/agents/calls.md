# Calls and voice

## Layout

- `voice` (audio type, voice-service client and its speech and turn detectors (`vad`, `turn`, `detector_state(part=…)`), spoken text without stage directions (`without_stage_directions`), `afconvert`)
- `call_audio` (a call's audio over the call helper's socket: frame in, frame out, end of turn (`TurnEnd`, one per call like `Barge`: the full pause, or sooner when Smart Turn, asked once a pause at the short pause about the last 8 s, is sure (p >= 0.8: at once) or probably sure (p >= 0.5: at 1.5 s), 3 failed or late answers in a row the full pause for the rest of the call; and the pause by speech, where a loud frame counts as pause once the speech detector rated every chunk it falls in as noise (rule R4, p < 0.1), so a turn never ends later than by loudness; no judge and no detector: today's listen, byte for byte; each listen's end kept, edited by calls.py, for the call's two end lines; `CallAudio.watch`: the caller going on after an early end), barge-in by loudness or speech: `Barge`), `calls` (voice calls: answer the allowed user, place a call for a reminder, the laid-back conversation, the end of a turn (one `TurnEnd` a call on the barge-in stream, the watch, the hold: `goes_on`), her own voice, summary), `voice_ready` (code's note "My voice is ready: you can call me now." after a long load or a call that rang while the voice was not ready)
- `tools/voice/`: the Swift voice service (WhisperKit + Kokoro for English, Supertonic-3 for the other ten languages, on the Neural Engine, and Silero VAD through FluidAudio for barge-in, on the CPU only; 127.0.0.1:8150), its core tested with Swift Testing.
- `tools/call-tunnel/` (AGPL-3.0-only, see its `LICENSE-NOTICE.md`): build script, pins and local patch for our signal-call-tunnel (the call helper signal-cli starts per call) and the JVM signal-cli installer.

## Commands

- Voice service: `cd tools/voice && swift test` (Swift Testing; XCTest is not available with the Command Line Tools; offline); real model (online, about 1 MB from Hugging Face, uses say): `VOICE_MODEL_TESTS=1 swift test --filter SpeechDetection`; run it after any FluidAudio or model-pin change; the turn detector's real model (Smart Turn, uses say; about 17 MB from Hugging Face at the pinned commit, or the pinned files from a folder you name, copied and checked): `VOICE_MODEL_TESTS=1 [VOICE_TURN_MODEL_DIR=<folder>] swift test --filter TurnDetection`; run it after any change to `TurnModel` or the download; Whisper's pinned files for real (online, about 1.6 GB, then a start on the CPU only): `VOICE_WHISPER_TESTS=1 VOICE_WHISPER_MODELS=<folder> swift test --filter WhisperStart`, then the same with the network denied: `sandbox-exec -p '(version 1)(allow default)(deny network-outbound (remote ip))' env VOICE_WHISPER_TESTS=1 VOICE_WHISPER_MODELS=<folder> swift test --disable-sandbox --skip-build --filter WhisperStart` (after `swift build --build-tests`; a start that needs the network fails there); run it after any WhisperKit or Whisper pin change; install: `scripts/install-voice-daemon.sh` (asks for sudo: the person runs it in their own Terminal window (asks for the Mac password)), which runs `estia-deploy --voice`: the build is the deploy's, as you, from the commit's own sources; every later deploy builds it again only when `tools/voice` changed (`voice_tree` in release.json), else keeps the live release's root-owned build

## Rules

- Voice notes: only the allowed user's audio is transcribed; audio that Signal does not mark as a recorded voice note (an audio file shared from elsewhere) is stored as `[audio file] …` (words typed with it stay on their own line below the transcript): not the user's words (never learned, never a yes, `remember`/`forget` refused, device changes wait for a yes; with `/voice echo on`, code's echo of it leaves its links out, `signal_text.unlinked`, while a voice note's echo is as heard); without the flag everything is a voice note as before; audio and spoken answers live only until used (deleted in `finally`, the sweeper catches leftovers); the voice service listens on 127.0.0.1 only, refuses browser-style requests and logs metadata only; the bridge sends it audio and text only over a connection a program of her own account took (`voice.peer_is_ours`: `lsof` run as her lists only her processes), else nothing, the part's reason `not_hers` (doctor and `/status`: the lsof line to find the program, then `estia stop voice` and `start voice`). Its WhisperKit and FluidAudio pins come from OpenWhisperer: change them only deliberately. Whisper's files are pinned too (`WhisperModel` in `ModelPin.swift`: the CoreML model and the tokenizer WhisperKit reads with it, one commit each, every file's sha256), checked at every start (`prepareModel`; about 0.6 s for 1.6 GB, read in pieces) and downloaded at that commit only when missing (`downloadPinned`, WhisperKit's own layout, so an existing copy is kept); WhisperKit then gets only the checked folders (`whisperConfig`: `modelFolder`, `tokenizerFolder`, `download: false`), so a start never reaches Hugging Face. A changed or added file (an older download's extra file too) or a link is never loaded and never downloaded over: `prepareModel` moves that pin's folder aside whole (`<folder>.refused-<UTC time>` beside it; only the latest such copy of a pin is kept, so the disk never fills), downloads the pinned commit into a fresh folder and checks it, so no recovery needs her user or root; changed again, or a folder that cannot be moved, listening stays `failed` with the service up (no restart loop); a failed download, or files still missing after it, exits so launchd tries again. The turn detector's files (Smart Turn v3.2 in the community CoreML port, `TurnModel` in `TurnDetector.swift`: one commit, all 8 files' sha256) follow the same rules through `prepareModel`, downloaded by `downloadPinnedFiles` (https only, redirects too, at the pinned commit, at most 32 MiB a file, into a staging folder moved into place); anything that fails leaves only the turn detector `unavailable` (the bridge waits the full pause), never a restart.
- Calls: only allowed ACIs are answered; strangers are ignored (never rejected: that would send them something); `accept_call`/`hangup_call`/`start_call` refuse other ACIs in code. Call audio lives only in memory; turns are stored as `[call] …` text (answered/sent at once, so recovery never re-sends them); logs hold metadata only. A device yes on a call counts only after she finished asking (the question's last sentence cannot be talked over); the question itself is spoken in code's words (`Devices.question`), so a yes never confirms something the caller did not hear. At the start of an ordinary call (not a practice call: `call_started(practice=…)`), with `[calendar]` or `[mail]`, code reads the call's glance (`call_host.CallGlance`: `MailDigest.glance` at once, a quick local read, and `CalendarTools.glance` in a task; `prompts.call_glance`): today's counts and times only, never a title, place, calendar name, sender or subject (that text would make the call outside text), last in the system prompt; she may offer the rundown (once: her first answer given with the glance that asks something, `CallGlance.note`); a whole yes right after it (`language.is_yes`: the call's language or English) makes code read today's calendar and the mail digest itself (`call_host.rundown_reads`, at most once a call: `calendar_agenda` for today and `mail_digest`, each when set up, run through `Brain.answer(reads=…)` as her own tool calls, logged and counted like hers; live evals: on her own she called no tool after the yes), else she reads details with the tools only when asked (that answer is outside text as ever); the mail counts are there from the first turn, which waits for the calendar's at most `GLANCE_WAIT_SECONDS`, later turns take them once read; each part has its own try (a calendar that fails in any way is "not read just now", the mail counts stay); it is dropped at the call's end. What stops her is `[calls] interrupt` (owner, 14 Oct): `interrupt = "only speech"` (the default; inside the code and the logs "speech": the voice service's speech detector, `POST /vad?stream=<call>` with 256 ms chunks: p >= 0.99 and the chunk louder than max(3x floor, 150)) or `interrupt = "any sound"` ("loudness"; the default before 14 Oct); the old `barge = "speech"`/`"loudness"` and the short forms `interrupt = "speech"`/`"sound"` are still read (`config.INTERRUPT_READ`), `interrupt` wins over a `barge` beside it, and doctor's "Calls setting" line gives the new wording (`Config.calls_interrupt_old`, `calls_barge_unread`); people read only the new words (doctor's Speech detector line says "any sound stops her"), the internal names stay (`Config.calls_barge`, `CallSettings.barge`, both "speech" by default); the other rule is a shadow, never acted on (`call_audio.Barge`): counted at most once a clip, only when the rule in charge did not stop her in that clip or its stop was no words or her own voice (`Barge.false_stop`), with stops and "would have" kept per rule; one end-of-call log line (metadata) names the configured rule, why loudness took over if it did, the counts per rule, the detector's chunks, slowest answer and failures by kind (`timeout`, `http`, `late`); the loudest chunk the level gate turned away at p >= 0.99 is one log line a clip (numbers only). No detector (`voice.detector_state`: loading, unavailable, old voice service, not ready), or 3 failed or late (> 600 ms of audio) answers in a row in a call, means loudness for the rest of it, and a call never waits for the detector; the pre-roll reaches back to the first frame of the latest chunk an answer may stop her on (`PREROLL_FRAMES`). After every stop the transcript is compared with what she already played (the sentence before and this one up to the stop, `calls.played_part`): her own voice (`calls.is_own_voice`: >= 3 of her content words, function words left out, >= 60% of the transcript's, and >= 3 words in a row as she said them; a stop, yes or no word she did not say makes it the caller's; Japanese by characters) carries on like a cough, never reaches Gemma, and the first time in a call a stop then needs 1.5x the level that stopped her (once, never compounding). A listener's acknowledgement (owner, 14 Oct; live, a listener's "okay" or "yeah" ended two answers and the rest was dropped): a transcript of only the call language's acknowledgement words (`language.ACKNOWLEDGEMENTS` and the hums Whisper writes, `ACKNOWLEDGEMENT_SOUNDS`, fillers beside them; `calls.is_acknowledgement`, Japanese by characters) carries on like a cough (from a little before the stop, never back to where she resumed or before: a stop sooner than `RESUME_BACK_S` after she resumed goes on from the stop, and after `MAX_FALSE_BARGE` of them in one clip she goes on from the stop itself, so each one takes her further), unless her sentence or the one before it ends with a question mark, or in Japanese with か (`calls.asks`), or a device question waits (`turn.asks_yes`): then it is the caller's answer. One asked back ("네?", "はい？", "Right?": "pardon?") is no acknowledgement, and one word asked back takes over. Logged "calls: an acknowledgement; carrying on" (no words), counted in the end line (`acknowledgements N`), never a false stop for the shadow and never one of `MAX_FALSE_BARGE`. Anything more ("okay, and tomorrow?", "yes but") takes over. One word alone takes over when it is a stop word ("stop", "wait", "no", "hold", "sorry", "hey", `language.INTERRUPTIONS`), a "but" (`language.BUT`, the 11 languages) or her name; a yes word alone (`calls.ANSWER_WORDS`, any language) only when she asked something or a device question waits. Each takeover after a stop by the caller's words (a lone "wait" and a goodbye too; never noise or her own voice) logs "calls: taken over (N words)" (`turn_words`). ## Gotchas

- The Neural Engine compiles a model on its first use: about 15 minutes for Whisper large-v3 turbo, cached per process name and macOS build (`~/Library/Caches/voice-service/`), so again after a macOS update. The voice service warms up at start and says "loading" until then. It compiles again per user: about 15 minutes after the move into her own user (live, 13 Oct), although the move copies the cache. Calls go unanswered meanwhile (hence the ready note).
- WhisperKit given `model:` and `downloadBase:` lists the repository at `main` and asks Hugging Face about every file at every start, fetching whatever changed; with no tokenizer in its folder it fetches one from `openai/whisper-large-v3` at `main`. Hence `whisperConfig` and the pinned tokenizer. WhisperKit names Hugging Face's address itself for that download step (`Constants.defaultRemoteEndpoint`), so `HF_ENDPOINT` cannot show that a start stays offline; `sandbox-exec` with outgoing connections denied can (SwiftPM's own sandbox cannot nest: `swift test --disable-sandbox --skip-build`). A Hub download keeps its records in `.cache` at the top of the repository's folder (inside the tokenizer's, beside the model's folder): `HubPin.check` leaves it out there only.
- `swift test` with only the Command Line Tools can lose the Testing macros plugin after a failed build; `tools/voice/Package.swift` names its folder (`-plugin-path`).
- Homebrew's signal-cli (GraalVM native) cannot place calls: it lacks reflection metadata for `TurnServerInfo` (also on master). Calls use the JVM build of the same version (`tools/call-tunnel/install-signal-cli-jvm.sh`); its launcher must not get `-D…` arguments (IPv4 goes in `JAVA_OPTS`).
- macOS stretches 10 ms sleeps to ~90 ms in background or idle processes (Claude Code jobs included): an audio clock must run on a real-time (time-constraint) thread, as our call helper's patch does, or the call sounds garbled. Test call timing in frames, never wall time.
- Call audio: estimate the line's floor from the quietest frames (capped), never from the first frames alone, or a caller who talks at once is not heard; drop what came in while she was thinking only when a new answer starts, never between two sentences.
- Barge-in by speech decides once per 256 ms chunk (FluidAudio 0.15.8's `VadManager` takes exactly 4096 samples at 16 kHz; shorter chunks are padded and break detection), so it stops her about 0.1 s later than loudness. Silero ignores loudness above a whisper: the level gate keeps a far voice out, whispers are mostly missed, and a radio, singing or a passenger counts as speech. Chunks go out in order (the service keeps one detector state per call); the answer lands on a later frame, so tests count it in frames.
- English speech (VoiceCore `SpokenEnglish`, Kokoro only) is one list of passes in one order (`SpokenEnglish.order`, pinned by a test): a pass that runs early owns its text (times take their colon, dates their numbers, units their amounts; symbols run just before the numbers are read, since their rules look at the digits). A new rule goes in its pass, with rows in `PronunciationTable` (`SpokenEnglishTests.swift`), the rows that must stay as written too: one test runs every row through `spokenInput`, which catches a pass in the wrong order. Every pattern is a `static let` (`Pattern`), compiled once (14 passes, about 55 patterns, on every sentence of a call). Capitals Kokoro reads as words ("ID") go in `EnglishLexicon` (FluidAudio checks the exact spelling first, so "id" keeps its reading), never in the text; lower-case letters Kokoro sounds out as a word ("uk", "www") are written in capitals for its own letter reading (live: "co dot uk" came back "co.oc"). Chords (`ChordSpeller`, the chord speech audit, 18 Oct): a run joins on spaces, commas, dashes, bars, arrows, semicolons (the bridge says a table's bar lines as "; "), slashes with a space before them (beat slashes), "…", "‖", "⏸" and "𝄐", each gap said as a comma (a semicolon or a slash only next to a chord or a mark said: "Take route A; B is closed" stays); a chart's marks are run members said as words among chords or in a sentence about music (`ChordSpeller.Mark`, one pattern the ten languages share: "N.C." "no chord" among chords, and alone in a sentence about music only where a chart puts it (`ChordSpeller.chartSpot`: after a colon, a music word or, in English, "on", "is" or "with"; never "NC" alone or a place, "lives in N.C.", "Raleigh, N.C.", "de N.C.": the review, 18 Oct); "%" "repeat" only between chords; a repeat after a chord said, a section's name ("Chorus x2") or a bracket at a clause's end (`ChordSpeller.endsClause`: "Buy strings (x2) for the guitar" is a quantity) "twice", "three times"); three chords or more in a row with sheet gaps alone between them (no comma, dash or word) that are their sentence alone (only marks, punctuation and bars around them: `standsAlone`) make a chord row, so its bare letters are major chords and an opening "A" is the chord, never the article, unless the letters run in alphabet order ("The A B C of") or the sentence is about notes ("The notes are G B D F"); inside a sentence such letters stay letters ("Standard tuning is E A D G B E", "Vitamins A C E": the review, 18 Oct), and a table row of answers ("| A | C | B |") is a known gap; "-" right after the root before a number is minor (ambiguous: "the A-7 south" stays; with a sharp or flat strong, "F#-7", in the ten languages alike: the review, 18 Oct), "CmMaj7" and brackets with "maj7", "add9", "no3" or alterations are strong.
- Speech in the other ten languages (VoiceCore `SpokenLanguage`, Supertonic-3 only) works the same way: one list of passes per language in one order (`SpokenLanguage.order`, pinned by a test), each language's words, tables and context lists in its pack (`Languages/Pack_<code>.swift`), numbers from Foundation's spell-out in the full locale (`Cardinals`: soft hyphens out, pt_PT's "mil milhões", ru's "ноль целых"; fr with spaces for hyphens, the live check), forms from hand tables (`Inflect`: last-word gender, the pl and ru plural rule, ordinals, pl and ru genitives and years), chords from their own parser (`ChordWords`), spelled only in a music context as in English (a strong chord anywhere; "G7", "C#", "Am" with the pack's music words, a strong chord, a run of three or a run that is the whole sentence; else "C#" is "C sharp"; ja and ko spell as before); every gap but a comma between two chords said is the pack's `dash` (", ", ja "、"), and the gaps are English's; es, it, pt, fr, nl, de, pl and ru also read "C-7", a minor chord with a major seventh, alterations (the sign by its name, then the number) and "(no3)" (`Style.forms`: a bracket with a bass or a sus keeps the reading from before, `plainCandidate`), and a chart's marks in their own words (`Style.marks`); ja and ko have neither, so their candidate is the one from before. A new rule goes in its pass, with rows in `LanguageTable` (`SpokenLanguageTests.swift`), the rows that must stay as written too; every row runs through `spokenInput`. Shared patterns are `static let`s; a language's own (month names, its ordinals, its currencies) are compiled once, when its reader is first made. ja and ko keep the digits Supertonic-3 reads right and rewrite only the failing pieces; letter classes next to a number are Latin and Cyrillic only, so kana and Hangul glued to it never block a match. Foundation's `Unit` class is why the units enum is `MeasureUnit`.
- Outgoing calls (signal-cli 0.14.9 `startCall`, experimental upstream): the `RINGING_OUTGOING` event comes before `startCall`'s reply, so the call id is not known yet when it arrives (`CallManager._dial` buffers events); `CONNECTING` only means it reached the phone. The end reasons (`ring_timeout`, `remote_hangup`, `remote_busy`, …) and pipe-mode audio on an outgoing call still need the live test (docs/e2e-checklist.md, 83-86).
